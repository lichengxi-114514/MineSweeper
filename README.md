# MineSweeper

首点绝对安全、支持纯逻辑推进提示的扫雷。核心逻辑层已完成，并通过千局交叉验证；
CLI 与图形界面在开发中。

## 1. 项目背景与目标

面向课间 5～10 分钟练习逻辑推理的学生。常见网页版扫雷有两个体验缺陷：
首次点击可能直接踩雷；中高级难度常出现只能靠猜的局面。

本项目提供：可离线运行、首点绝对安全、并能提示“当前是否还能纯逻辑推进”的扫雷。

**已实现**（截至标签 <当前 tag>）：
- 可复现的盘面生成（单一随机入口 `core/rng.py`，同 seed 同盘面）
- 首点及其 8 邻域保证无雷，0 区自动展开
- 翻开 / 展开 / 胜负判定的完整状态机
- 独立参考实现与千局交叉验证

**计划中**：插旗与和弦展开、求解器（R1/R2）、CLI、图形界面、无猜测棋盘生成。

## 2. 课程知识与核心设计

### 2.1 数据结构

| 结构 | 选择 | 理由 | 代价 |
| --- | --- | --- | --- |
| 雷位与邻域数 | 一维 `bytearray`，含哨兵边框 | 邻域枚举变成对 8 个固定偏移的访问，结构上不可能越界；单格 1 字节，`-1` 混编码被类型本身禁止 | 索引算术错误不会被解释器发现，需靠 `_off()` 单一出口约束 |
| 已翻开/已插旗集合 | `set[tuple[int,int]]` | 成员查询 O(1)，`len()` 即翻开计数，胜负判定 O(1) | 每格约 32B；100×100 时约 600KB，当前规模可忽略 |

### 2.2 算法

- **延迟布雷**：构造时不布雷，首次 `reveal` 才以 `forbid = 首点及 8 邻域` 布雷。
  由此首点安全是**结构保证**，不是概率事件。
- **0 区展开用 BFS**（`collections.deque`），不用递归。实测依据：
  参考实现的递归版在 40×40 全 0 盘面触发 `RecursionError`
  （`tests/test_reference.py::test_experiment_recursion_limit_40x40`）。
- **展开的正确性依据**：只有 `adjacent_at == 0` 的格才传播，而 0 格的定义
  保证其 8 邻居均非雷，因此雷格不可能被入队——`_flood` 内不判断雷，
  这不是省略防御，而是不变量。

### 2.3 复杂度

| 操作 | 时间 | 空间 |
| --- | --- | --- |
| 布雷 + 邻域预计算 | O(k) 抽样 + O(8N) | O(N) |
| `reveal` 单格 | O(1) | — |
| 0 区展开 | O(R)，R 为实际翻开格数 | O(R) |
| 胜负判定 | O(1)（比较 `len(_revealed)`） | — |

### 2.4 验证方法

沿用“独立裁判”的思路：`tests/reference.py` 是一个不 import 本项目任何模块的
朴素实现（递归 DFS、每次现算邻域数），与正式实现交叉验证结果集合。
遍历顺序不同（DFS vs BFS），只比较集合，不比较顺序。

## 3. 安装与运行

**当前版本只提供逻辑层，尚无界面。** 下面的命令用于运行测试与调用 API。

```bash
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -e .                 # 使 python -m minesweeper 可用
pip install -r requirements-dev.txt
pytest -q
```

最小使用示例：

```python
from minesweeper.core import Game, GameState

g = Game(9, 9, 10, seed=42)
g.reveal(4, 4)                      # 首次点击触发布雷，返回本次翻开的格子
print(g.state, len(g.revealed_cells))
```

环境：Python 3.10+，运行时零第三方依赖（仅标准库）。

## 6. 局限与改进

**功能缺口**（按优先级）：
- 插旗与和弦展开：实现中
- 求解器（R1 单点规则 / R2 子集差集规则）与逻辑推进提示：未开始
- 无猜测棋盘生成（生成-求解-重试）：未开始，属加分项
- CLI 与图形界面：未开始
- 给安全格插旗会阻止该格被翻开，从而无法通关，需撤旗后手动翻开。
  这是“旗格阻断展开”与“胜利 = 所有非雷格被翻开”两条规则的必然推论。

**已知限制**：
- 可复现性只在同一 Python 版本内保证（`rng.sample` 的实现细节可能变化）。
  `examples/` 中的盘面以 hex 形式保存，不依赖“用 seed 重跑”。
- 任一边 ≤ 3 的棋盘雷数上限为 0（3×3、2×2、1×3 无法布雷）。
  这是“任何首点都能开局”这一设计（D6）的代价。
- 给安全格插旗会阻止该格被翻开，从而无法通关，需撤旗后手动翻开。
  这是“旗格阻断展开”与“胜利=所有非雷格被翻开”两条规则的必然推论。
- 求解器最坏情况为指数级，届时需限制连通块规模并设超时。
