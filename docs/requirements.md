# 扫雷（MineSweeper）需求与验收标准

> 状态：v0.1（M0 需求冻结）。后续若改变功能范围，请在此文件记录变更。

## 1. 目标与使用场景
面向课间 5～10 分钟练逻辑推理的学生。现有网页版扫雷的两处体验缺陷：
1. 首次点击可能直接踩雷，随机性劝退新手；
2. 中高级难度常出现"必须靠猜"的局面，推理被随机性打断。

本项目提供：可离线运行、首点绝对安全、并能提示"当前是否还能纯逻辑推进"的扫雷。

## 2. 功能范围
| 编号 | 功能 | 优先级 |
| --- | --- | --- |
| F1 | 可 seed 的棋盘生成，雷数恒定 | 必须 |
| F2 | 首点安全（首点及 8 邻域无雷），0 区自动展开 | 必须 |
| F3 | 左键翻开 / 右键插旗 / 双击和弦 | 必须 |
| F4 | 胜负判定与计时 | 必须 |
| F5 | CLI 文本界面（测试与无图形环境演示用） | 必须 |
| F6 | 求解器 R1（单点规则）、R2（子集差集规则） | 必须 |
| F7 | 提示下一步可确定的安全格 / 雷格 | 必须 |
| F8 | 无猜测棋盘生成（生成-求解-重试） | 加分 |
| F9 | Tkinter 图形界面 | 必须 |
| F10 | 难度预设 + 自定义行列雷数 | 必须 |

## 3. 明确不做（非目标）
联机对战、排行榜、公网部署、皮肤与音效、撤销操作、移动端适配、自动求解整局。

## 4. 验收标准
| 编号 | 标准 |
| --- | --- |
| A1 | 同一 (rows, cols, mines, seed) 生成的盘面完全确定，雷数恒等于设定值 |
| A2 | 随机 10000 次首点，踩雷次数 = 0 |
| A3 | 翻开/展开结果与参考实现逐格一致，1000 局随机对比 0 差异 |
| A4 | 边界：1×1（mines=0）、2×2 与 3×3（构造期上限 0）、9×9（构造期上限 72）、
      1×9（上限 6）；Board 层单格上限：9×9 角 77 / 边上 75 / 内部 72。
      超上限抛 ValueError，消息含"所需 / 可用 / 首点坐标"。 |
| A6 | 已翻开格不可插旗；插旗格不可被翻开；重复点击无副作用 |
| A7 | 胜利 = 所有非雷格被翻开；踩雷立即 LOST |
| A8 | 同一 seed 下 CLI 与 GUI 的最终盘面一致 |
| A9 | 求解器可解时提示正确；无法推进时返回 unknown，不给出猜测 |
| A10 | 按 README 在干净目录重装重跑，全流程可复现 |

## 5. 技术选型与依赖
- Python 3.10+；GUI 用标准库 Tkinter。
- 运行时零第三方依赖；开发依赖仅 pytest。
- 可复现性定义：所有随机性来自唯一入口 `core/rng.py`，测试固定 seed。

## 6. 风险与对策
| 风险 | 对策 |
| --- | --- |
| 无猜测生成过慢或失败率高 | 限定规模、设重试上限、如实统计并写入"局限" |
| 求解器规则无限加码 | 分级交付，R3（全局约束）明确标注未做 |
| GUI 引入新 bug | core 层被 pytest 全覆盖，GUI 只做人工冒烟清单 |
